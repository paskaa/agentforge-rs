# VERDICT 协议校准手册

> 基于 Anthropic Harness Engineering 最佳实践的评估器校准标准

## VERDICT 输出格式

所有 Reviewer（华佗验收、张飞测试、荀彧DB审查）的输出**最后一行**必须是：

```
VERDICT: PASS [可选: 简短说明]
VERDICT: FAIL [具体失败原因]
```

## 评估维度 (4维评分)

| 维度 | 说明 | 权重 | 评分标准 |
|------|------|------|----------|
| 设计质量 | 模块间命名规范、错误处理模式、API设计风格是否全局统一 | 25% | 1=混乱 3=基本统一 5=严格一致 |
| 工艺性 | 边界条件覆盖、类型安全、性能热点处理、日志充分 | 25% | 1=粗糙 3=基本完善 5=精雕细琢 |
| 功能性 | 功能是否按预期工作、测试是否通过、用户路径是否畅通 | 30% | 1=不能用 3=基本可用 5=完美运行 |
| 风格一致性 | 与项目现有代码风格的匹配度 | 20% | 1=格格不入 3=基本一致 5=浑然一体 |

**通过线**: 总分 ≥ 12/20 且 功能性 ≥ 3

## PASS 校准样本

### 样本 1: 前端Bug修复 — PASS

```
Bug #462: 目录管理-诊疗目录 编辑弹窗中所需标本下拉框数据加载失败

修复内容:
- 修改 src/views/basicmanage/caseTemplates/index.vue 第128行
- 添加 getSpecimenList API 调用
- 在 onMounted 中初始化下拉数据

评估:
- 设计质量: 4 (遵循了项目现有的 API 调用模式)
- 工艺性: 4 (添加了 loading 状态和错误处理)
- 功能性: 5 (下拉框正常加载数据，编辑保存正常)
- 风格一致性: 4 (与项目其他下拉框组件风格一致)

VERDICT: PASS [功能性完整，无回归]
```

### 样本 2: 后端Bug修复 — PASS

```
Bug #456: 门诊医生站：诊疗类医嘱保存后类型变更为检查

修复内容:
- 修改 src/main/java/.../OrderServiceImpl.java 第256行
- 在 saveOrder 方法中添加 orderType 字段的正确赋值逻辑

评估:
- 设计质量: 4 (Service层逻辑清晰)
- 工艺性: 3 (基本的参数校验，日志可接受)
- 功能性: 5 (保存后类型正确，查询也正确)
- 风格一致性: 4 (与现有 Service 实现风格一致)

VERDICT: PASS [问题根因定位准确，修复最小化]
```

## FAIL 校准样本

### 样本 3: 修复不完整 — FAIL

```
Bug #471: 手术管理-门诊手术安排 查询结果混入住院检验申请单

修复内容:
- 修改了查询条件，但只处理了列表查询
- 未处理统计接口的相同问题

评估:
- 设计质量: 3 (查询条件设计合理)
- 工艺性: 2 (未处理所有相关接口)
- 功能性: 2 (列表查询正常，但统计仍混入数据)
- 风格一致性: 4 (代码风格一致)

VERDICT: FAIL [功能修复不完整，统计接口未处理]
原因: 只修复了列表查询，统计接口(StatisticsController)存在相同问题
```

### 样本 4: 引入新问题 — FAIL

```
Bug #465: 检验报告 查询超时

修复内容:
- 添加了 SQL 索引
- 但修改了查询逻辑，导致部分数据丢失

评估:
- 设计质量: 2 (修改了不应修改的查询逻辑)
- 工艺性: 2 (未验证修改后数据完整性)
- 功能性: 1 (查询速度提升但数据不完整)
- 风格一致性: 3 (代码风格基本一致)

VERDICT: FAIL [修复引入新问题]
原因: 修改了 QueryWrapper 的过滤条件，导致 status=CANCELLED 的记录被错误排除
```

### 样本 5: 编译失败 — FAIL

```
Bug #480: 收费管理 退费失败

修复内容:
- 修改了 RefundService.java
- 但引入了未导入的类

评估:
- 设计质量: N/A
- 工艺性: N/A
- 功能性: 1 (编译失败，功能不可用)
- 风格一致性: N/A

VERDICT: FAIL [编译失败]
原因: 缺少 import com.healthlink.his.charge.entity.RefundRecord
```

## 调优流程

1. **系统性阅读评估器日志**: 不只看 PASS/FAIL，逐行阅读推理过程
2. **识别判断偏差**: 对比人工判断 vs 评估器判断
3. **更新 Prompt 并复测**: 用同一批测试用例复测，通常 3-5 轮迭代
4. **持续监控漂移**: 定期人工抽检，尤其是更换模型版本后

## 降级测试标准

当 Playwright 测试失败/超时时，降级到接口健康检查：
- 后端服务可达 (HTTP 200/401)
- 核心 API 响应正常
- 数据库连接正常

降级通过条件：所有健康检查项通过

## 降级验收标准

当验收超时时，降级到自动验收：
- Git commit 存在 (grep Bug#xxx)
- 编译通过 (mvn compile)
- 无新增编译警告

降级通过条件：所有自动检查项通过
